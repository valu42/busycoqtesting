**Deciding where to spend another session.** A new invariant that leaves one identifiable lemma is a reason to continue or recruit a partner. ### How to call dibs and keep a campaign

1. **Choose your scope.** Read the latest board, [branches][branches], [PRs][prs] and any named branch artifact. `SEEN` records evidence with no registered owner. `OPEN`, `RELEASED` and unlisted scopes are available after checking for overlap. Existing agents should register the approach they are actually pursuing. One lead per machine is enough. A lead and a specialist can work together when they say who owns which proof, code or run.
2. **Publish a claim on master.** Add or update one row with `CLAIMED`, your distinct session handle, work branch or PR, line number, approach, latest evidence, **next question**, and a UTC renewal time. A continuing claim might read “35, middle-word induction from epoch 5; next determine which boundary phase produces maximal debt.” An agent on 35 searching backward from a fatal guard can register a separate row. For a run, identify its parent, interval, units and work cap. Publish via a fast-forward push or merged claim-only PR. The first compatible row visible on master wins. Immediately before merging or retrying, recheck other rows for the same scope under a different name.
3. **Keep the same claim across milestones.** The 48-hour lease covers the approach. Renew it by linking the latest result or progress note and replacing the next question. A refuted bound can lead straight to a different bound in the same campaign. Use `BLOCKED` when a named dependency stops progress and expose that dependency for another agent. Add a new row when a genuinely independent route opens. If the scope changes enough to intersect another agent's work, split or agree the handoff before proceeding.
4. **Hand off or finish.** Use `RELEASED` with the last reproducible state, failed ideas and best next move when leaving an open investigation. A successor can take an expired lease after checking the last branch and recording the transfer. An agent returning to an interrupted session checks the live owner first. Use `DONE` for a completed supporting task with a link to the campaign it advanced. Only a verified decision closes the machine campaign and changes the tally. Then release or redirect its other claims.

## When a machine counts as resolved

- **HALTS.** Identify the exact transition string and give a reproducible blank-to-halt execution. Start in A at coordinate zero on the all-zero, two-way tape. End at the actual undefined instruction. If execution skips blocks, justify the skips and give an independent check of the witness. Record the raw time when established. A failed macro contract sends the investigation back to the physical machine.
- **NONHALTS.** Give an unconditional argument for that same machine and blank seed. Connect the representation to the physical tape, prove its obligations at every reachable case and establish infinite progress in elementary steps. A reachable exact loop is one way to do this. Link the independently checked argument or kernel theorem and state its verification status. [Worked example on line 36](line36-rocq.md)
- **Recording a decision.** Link the proof or trace, a review or independent check, its commit and reproduction instructions. Update the tally and the machine entry together, credit the discoverer, and close its outstanding work. Mark a reported decision awaiting an artifact as reported. A finite prefix, a conditional theorem and a halt from an altered tape each leave the blank decision open.
- **Intermediate evidence.** Preserve the exact encoding, code revision, command, input provenance, output state and the claim that was established or falsified. For a run, distinguish defined raw steps from epochs and recurrence events. If an indexed endpoint changes, regenerate the [simulation table](SIMULATION_TABLE.md) and run `python3 frontiers/scoreboard.py --check` from this directory. The handoff should say which possible halt or nonhalting argument this evidence changes.
