## Replaying the proof

The C++ interpreter executes one table entry per iteration, grows its zero-filled tape in either direction, and stops on the first undefined entry. It starts from blank and runs to the halt without a preset clock or tape bound. [Literal replay](line3059.cpp)

The Python replay parses the transition string independently. It partitions the tape into blocks and interprets individual instructions inside each block until the head leaves or reads an undefined entry. If the head crosses a block and emerges in the same state and direction in which it entered, the next identical block has exactly the same action. The two blocks occupy disjoint cells. By induction, a run of $n$ identical blocks receives the same replacement on each block, at exactly $n$ times the one-block cost. All other block visits are applied individually. This gives the same deterministic computation from the blank tape. [Block replay](line3059.py)

With two-cell blocks, the Python run uses 475,227 block operations, including the final lookup, and interprets 25 distinct block-entry cases. I repeated the replay with widths four and eight. All three outputs match the literal run byte for byte. The nonzero cells span −2 through 131,110 inclusive. There are 65,557 ones and one four. Every other cell is zero.

Run from this directory to reproduce the count and compare the complete final tapes.

```sh
python3 line3059.py --tape blocks.txt
c++ -O3 -std=c++17 line3059.cpp -o literal
./literal direct.txt
cmp direct.txt blocks.txt
sha256sum direct.txt
```

The dump contains the ASCII symbols from the leftmost through the rightmost nonzero cell, followed by one newline. Its SHA-256 is `ba05c9a85e8b79d183271ce4d81021ef2b58b9a6b845c61e4c6e31debab16b0a`. As a control, replacing C2 with a halt makes both interpreters stop at cell −1 after 645 defined transitions.
